# 高并发代码修复任务设计

本文基于 [BACKGROUND.md](./BACKGROUND.md) 定义的场景给出最小实现设计。具体实施步骤见 [执行计划.md](./执行计划.md)，本机验证方案见 [ACTUAL_IMPLEMENTATION.md](./ACTUAL_IMPLEMENTATION.md)。

## 1. 目标任务

在不改变 RepoFixLab 单任务执行语义的前提下，让平台稳定接收 1,000 个集中提交任务，并把同时执行数量严格限制为 200。

设计目标：

- 高峰流量先进入队列，不直接冲击执行环境。
- 每个任务拥有独立工作区、状态、日志和制品目录。
- 同一请求重复提交只产生一个任务。
- 执行节点退出后，任务能够被发现并进入明确恢复流程。
- 上游服务并发独立受控。
- 补丁进入交付流程前完成基线检查。
- 每个终态任务都有结果制品；失败任务具有稳定失败原因。

成功标准：

- 活跃任务数量不超过 200。
- 工作区交叉写入数量为 0。
- 重复请求产生的新任务数量为 0。
- 丢失终态的任务数量为 0。
- 同名制品覆盖数量为 0。
- 基线过期补丁直接进入合并流程的数量为 0。

## 2. 核心原则

- **跨任务并发，单任务串行**：单任务内的模型轮次、文件修改、测试和状态转换保持原有顺序。
- **先排队，再占资源**：排队任务不创建工作区，不启动容器。
- **一任务一工作区**：同仓库任务也不共享可写目录。
- **任务 ID 贯穿全链路**：状态、日志、补丁、测试报告都绑定任务 ID。
- **完成晚于证据落盘**：结果制品写入成功后，任务才能进入完成状态。
- **合并晚于基线检查**：目标分支变化后，补丁必须重新验证。

## 3. 核心功能与模块

### 3.1 任务准入

职责：

- 校验仓库、基线提交、任务内容和调用身份。
- 接收客户端幂等键。
- 生成稳定任务 ID。
- 拒绝重复内容冲突。
- 写入初始任务状态。

最小规则：

- 相同幂等键与相同请求返回同一任务 ID。
- 相同幂等键与不同请求返回冲突错误。
- 任务持久化成功后才向客户端返回接收成功。

### 3.2 任务队列与调度器

职责：

- 保存待执行任务。
- 按提交顺序分配执行名额。
- 将全局活跃任务限制为 200。
- 对模型调用、Git 访问、测试执行分别设置并发闸门。
- 在资源不足时停止出队。

首版使用先进先出规则。任务优先级规则标记为待确认。

### 3.3 工作区管理器

职责：

- 为每个任务创建独立目录。
- 从冻结基线准备仓库内容。
- 为依赖缓存提供只读共享入口。
- 在任务终态后回收临时资源。

目录必须包含任务 ID。工作区不得写入源仓库目录，不得复用其他任务的可写缓存。

### 3.4 任务执行器

职责：

- 复用现有 RepoFix Agent、Controller、Worker、Evaluator 流程。
- 执行代码读取、模型调用、文件修改、测试和补丁生成。
- 遵守任务时限与上游并发闸门。
- 定期更新租约。
- 在安全点保存 checkpoint。

执行器不负责决定全局调度顺序。

### 3.5 状态与租约管理

职责：

- 保存任务状态和状态版本。
- 防止两个执行器同时拥有同一任务。
- 识别退出节点留下的失效任务。
- 保存恢复原因与恢复次数。

初始参数：

- 租约有效期：60 秒。
- 心跳间隔：20 秒。
- 连续两个心跳周期未更新后进入恢复检查。

以上参数需要通过压测确认。

### 3.6 结果与基线检查

职责：

- 按任务 ID 保存补丁、日志、测试报告和资源账本。
- 先写临时结果，再发布不可变结果清单。
- 比较任务基线与目标分支当前提交。
- 基线变化时将任务标记为 `revalidation_required`。
- 结果发布完成后再回收 Worker、Evaluator 和工作区。

### 3.7 监控与审计

首版必须记录：

- 队列长度。
- 活跃任务数。
- 各阶段耗时。
- 工作区创建失败数。
- 上游限流次数。
- 租约失效数。
- 恢复任务数。
- 残留资源数。
- 单任务模型用量与测试耗时。

## 4. 最小执行流程

```text
提交任务
  → 幂等校验
  → 写入 queued
  → 等待执行名额
  → 取得租约
  → 创建独立工作区
  → 执行 Agent 与测试
  → 生成补丁和报告
  → 检查目标分支基线
  → 发布结果清单
  → 回收资源
  → 写入终态
```

## 5. 状态模型

```text
queued
  → preparing
  → running
  → validating
  → publishing
  → completed
```

异常状态：

- `recovering`：租约失效，等待恢复检查。
- `revalidation_required`：目标分支基线已经变化。
- `failed`：任务无法继续执行，已保留失败证据。
- `cancelled`：任务在允许取消的阶段被终止。

状态更新必须携带上一版本号。版本不匹配时拒绝写入，防止并发覆盖。

## 6. 边界条件与限制

- 全局执行并发固定为 200。
- 排队数量上限待确认。
- 单仓库执行并发待确认。
- 单租户执行并发待确认。
- 单任务执行时限待确认。
- 上游服务配额待确认。
- 任务执行期间不自动跟随目标分支更新。
- 基线变化后不自动修改补丁。
- 一个任务只允许一个有效执行租约。
- 无完整 checkpoint 的失效任务不自动从中间状态继续。
- 结果清单发布失败时，任务不得标记完成。
- 取消语义待确认；首版只保证排队任务可以取消。
- 持久化数据库固定为 PostgreSQL，队列由任务表和事务领取实现。
- 首版不改变现有前端。

## 7. 故障处理规则

- **重复提交**：返回已有任务，不创建新任务。
- **执行器退出**：租约失效后进入 `recovering`。
- **存在完整 checkpoint**：新执行器从 checkpoint 继续。
- **缺少完整 checkpoint**：任务进入 `failed`，保留现场证据。
- **上游限流**：停止对应闸门出队，已运行任务等待下一次调用名额。
- **工作区空间不足**：停止新任务出队，触发资源告警。
- **结果发布失败**：保持 `publishing`，记录失败原因，不提前清理本地结果。
- **目标分支变化**：进入 `revalidation_required`，不直接交付补丁。

## 8. 风险

| 风险 | 直接后果 | 控制措施 |
| --- | --- | --- |
| 200 个任务同时启动 | CPU、内存、磁盘瞬时打满 | 调度器分批启动，活跃数硬限制 |
| 多任务共享工作区 | 文件与 Git 状态互相覆盖 | 一任务一工作区 |
| 客户端重试 | 重复费用与重复补丁 | 幂等键与稳定任务 ID |
| 长任务占满名额 | 后续任务长时间排队 | 执行时限与阶段耗时监控 |
| 模型服务限流 | 大量任务等待模型响应 | 独立模型并发闸门 |
| 依赖缓存并发写入 | 缓存损坏、安装失败 | 共享缓存只读，任务缓存独立 |
| 执行节点退出 | 任务卡死、资源残留 | 租约、恢复检查、资源回收 |
| 目标分支持续推进 | 补丁失效 | 基线检查与重新验证状态 |
| 结果路径重复 | 制品被覆盖 | 任务 ID 路径与不可变结果清单 |
| 指标维度过多 | 监控系统压力上升 | 聚合指标不携带高基数字段 |

## 9. 建议开发顺序

### 阶段 1：冻结任务契约

- 定义任务 ID、幂等键、状态机、失败原因。
- 定义结果清单与目录规则。
- 先完成状态转换测试。

### 阶段 2：跑通单任务队列

- 接入任务准入。
- 任务统一经过队列进入现有执行流程。
- 并发上限先固定为 1，验证行为没有变化。

### 阶段 3：实现工作区隔离

- 建立一任务一目录。
- 隔离 Git 状态、临时文件和可写缓存。
- 验证同仓库任务同时运行时没有交叉写入。

### 阶段 4：增加有限并发

- 引入执行名额管理。
- 按 10、50、100、200 的顺序扩大并发。
- 每个档位检查资源使用、错误率和完成时间。

### 阶段 5：加入租约与恢复

- 增加心跳、失效检查、checkpoint 恢复。
- 注入执行器退出、网络中断和存储失败。
- 验证任务都进入明确终态。

### 阶段 6：加入上游保护

- 分别限制模型、Git、测试和制品写入并发。
- 记录等待时间与限流次数。
- 根据生产配额调整闸门参数。

### 阶段 7：加入交付检查

- 对比任务基线与目标分支当前提交。
- 将过期补丁转入重新验证流程。
- 完成 1,000 任务、200 并发压测。

## 11. 上线前验收

- 1,000 个任务均被接收并获得稳定任务 ID。
- 活跃任务数量始终不超过 200。
- 相同幂等键重复提交只返回一个任务。
- 同仓库并发任务没有文件交叉写入。
- 执行节点退出后没有长期运行状态。
- 所有终态任务都具有结果清单；失败任务具有稳定失败原因。
- 结果清单发布前没有任务进入完成状态。
- 基线过期补丁没有直接进入交付流程。
- 压测结束后没有残留 Worker、Evaluator 和工作区。

API 延迟、任务完成时限、队列等待时限需要真实压测数据，当前标记为待确认。
