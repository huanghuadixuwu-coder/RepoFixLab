本文记录用户逐项确认的规则，替代助手此前自行冻结的 F1 草稿。

## 1. 池中没有合适容器，或池中容器故障

- 池里没有合适容器：正常按需创建。
- 池中容器启动失败或检查发现污染：销毁异常容器，确认清理完成后，尝试按需创建。
- 当前任务的故障角色后续保持按需模式；Worker 池故障影响该任务的 Worker。
- 按需创建失败时，按下列资源不足、Docker 不可用、镜像校验或配置错误规则处理。
- 异常容器销毁失败：隔离并保留资源占用；剩余额度允许时可创建替代容器。

## 2. 临时资源不足

- 当前任务回等待队列，保留已有进度，由统一调度在资源释放后重新申请准入。
- 沿用现有 5 分钟准入等待；超时标记资源阻塞，停止自动重试。
- 用户取消则结束等待。
- 已明确资源不足期间，不反复调用 Docker 创建容器。

## 3. Docker 不可用

- 暂停向该 Docker 实例派发新任务。
- 每 5 秒统一轮询一次可用性，最多等待 5 分钟。
- 尚未创建容器的任务保留在等待状态；正在执行的任务标记为执行状态待核对。
- Docker 恢复后检查已有容器和操作结果，再决定继续、取回已完成结果，或按 Worker／Evaluator 规则恢复。
- 超时仍不可用：标记基础设施阻塞，保留进度和资源记录，停止自动恢复。
- 用户取消则结束等待。

## 4. 镜像身份或内容不符、配置错误

- 镜像身份或内容校验不符：阻塞依赖该镜像的任务。
- 任务配置错误：阻塞对应任务。

## 5. Worker 执行过程中退出

- 先核对已完成操作，清理旧容器，再创建新 Worker。
- 优先恢复当前阶段最近的有效检查点；没有则向前查找上一阶段、更早阶段。
- 恢复检查点对应代码和阶段状态，重新执行之后未可靠完成的工作。
- 每任务最多自动恢复 **1 次**；新 Worker 不刷新计数。
- 再次退出时已经用完恢复额度，或所有阶段都没有有效检查点：终止并记录失败。
- 恢复创建仍受前述准备失败及清理规则约束。

用户指出所有阶段都没有检查点的情况很少见；规则仍明确该分支的终止行为。

## 6. 补丁快照保存失败

- 保存成功但响应丢失：查询并取回已有快照。
- 确认未保存成功且 Worker 正常：保留当前代码，额外重试保存 **1 次**。
- 重试仍失败：终止并记录原因。
- Worker 同时退出时，沿用第 5 节恢复规则。

## 7. Evaluator 评测失败

- 评测进程因基础设施故障中断：清理异常环境后创建新 Evaluator，对同一份已封存补丁重新评测。
- 每任务最多额外重评 **1 次**；再次失败则终止并记录原因。
- 评测已完成但结果响应丢失：查询并取回已有结果。
- 评测正常完成且测试未通过：归档正式结果，结束本次任务。

Worker 恢复和 Evaluator 重评分别按各自确认的 1 次限制计数。

## 8. 容器重置或销毁失败

- 重置失败：直接销毁容器，保留已完成任务结果，不重复重置。
- 销毁失败：自动再尝试销毁 **1 次**。
- 仍失败：隔离容器，记录残留资源，保留相应资源占用，等待人工处理。
- 清理故障发生后，已完成的任务结果保留。

## 9. Agent 职责边界

- IMPLEMENT 按计划生成首版补丁；实现错误和遗漏由 REFINE_1／REFINE_2 处理。
- PLAN 完成后计划固定，后续阶段没有重新规划职责。
- 执行中断从检查点恢复，重新执行未完成的工作，遵守原阶段职责。
- 已有阶段产物校验与有限次补交继续使用。
